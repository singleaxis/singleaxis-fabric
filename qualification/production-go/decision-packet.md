# Bounded production GO packet — owner intake and stop rule

Status: **NO-GO**. This is an approval-ready evidence index, not an approval
or a claim that the current synthetic fixture is a production agent. The
customer owns the target boundary and every signature. Fabric OSS supplies
only passive CAPTURE → PROTECT → DELIVER; evaluation and governance remain
outside its release artifacts.

## 1. Frozen claim to approve

The only candidate claim is historical reconstruction of the declared,
observable model → no-shell subprocess → allowlisted file-artifact → model
route. It does **not** include provider-hidden state, deterministic replay,
PTY/SSH/DB/browser/cloud/sandbox routes, unwrapped HTTP/subprocess calls,
background jobs, arbitrary descendants or non-allowlisted files. The latter
routes are currently reachable in a developer process; they are not excluded
from a production claim until customer controls prove them unreachable.

The [provisional scope](../synthetic-slice/scope.v1.json) names the existing
Python 3.11 fixture and required roles: provider-bound request and response,
approved HTTP/cwd context, terminal argv/stdin/stdout/stderr, and artifact
after bytes (plus before bytes on modification). Its byte, queue, stream and
outage limits are **test ceilings, not measured production capacity**. Before
signing, replace these fields with the actual agent build digest, model
endpoint/versions, workload and source identities, every reachable route,
exact content opt-ins, target rates/outage, privacy/retention schedule and
independent truth systems. Number the revision and freeze it *before* the
pilot. Do not retrofit scope after seeing discrepancies.

## 3. Target-environment intake (no secrets in this file or chat)

The operator provides an approved isolated staging cluster name/access
method, region and enforcing CNI; a customer-controlled OTLP destination
with independently queryable durable records; a separate content store;
KMS/IAM/retention/backup owners; an exact agent image and model endpoint;
and approved synthetic-only workload identity. The security owner names the
historical-secret reviewer. Access is provisioned through customer IAM and
short-lived credentials, never committed to the repository. Existing local
Kubernetes contexts are not authorization to deploy or capture.

## 4. One-pass decision procedure

1. Freeze and review code/config. Build the release candidate **once** from
   one clean commit; publish immutable image/package digests and a config
   digest. Do not make documentation commits to chase CI digests. A rebuilt
   chart/image is a different candidate unless byte-identical.
2. Pre-register scope, limits, fault seeds and expected independent records.
   Execute the spec-038 fault matrix and spec-039 storage, privacy and pilot
   tests against those exact installed artifacts in the approved environment.
3. Archive raw test outputs, destination readback, content digests, source
   truth, artifacts, commands, configuration and negative results in the
   customer evidence store. Reviewers independently verify hashes and
   receipts; matching aggregate counts alone are insufficient.
4. Mark **NO-GO** for any unknown/missing source, reachable uninstrumented
   route, unverified role/object, missing durable receipt, target control
   failure, unresolved security finding, or absent approval. Only the
   customer's named risk owner may issue a scoped GO after every required
   reviewer signs the same frozen packet.

An engineering or CI pass cannot sign on behalf of the customer. A narrow
metadata-only or synthetic shadow deployment may be approved separately,
but may not be described as complete content capture or compliance-grade
reconstruction.
