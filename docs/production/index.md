# Go to production

A production deployment records the same fields as the laptop path; what
changes is that the record is **authenticated, protected, durable and
encrypted**: TLS and a token on every hop, a capture policy you write, an
encrypted spool, a durable queue, and sensors bound to their own ingress.
Production needs no code change.

On a single host, `fabric init --production` does steps 1 to 3 and 5 for
you: it writes the capture policy into your project for you to review, and
generates every key, token and certificate. Starting the production Node
(`fabric up`) and checking it (`fabric verify --production`) on a single
host are not part of this release yet (`FC-011`): start the Node from the
settings `init` writes (`.fabric/node.env`) by the manual route below, and
`make -C deploy/compose preflight-prod` checks the host before you start
it, each failure with its fix.

| Step | Single Linux host | Kubernetes | Checked by |
|---|---|---|---|
| 1. Choose where records go | [destinations](destinations.md) | [destinations](destinations.md) | `preflight-prod`: egress URL, Authorization header, CA |
| 2. Keys, tokens and certificates | generated by `fabric init --production` ([secrets](secrets-and-rotation.md)) | generated in the cluster | `preflight-prod`: file modes, token strength, certificate names |
| 3. The capture policy | written into your project by `fabric init --production` ([privacy and security](../reference/privacy-and-security.md)) | the chart's `injector.capturePolicy` | the SDK refuses production without one (`FW-008`); `init` refuses one the SDK would refuse (`FC-167`) |
| 4. Start the Node, the destination and the sensor | [Linux host](linux-host.md) | [Kubernetes](kubernetes.md) | `preflight-prod`; `fabric verify --kubernetes` |
| 5. Size the queue and spool | `node.queue_size` ([sizing](sizing.md)) | [sizing](sizing.md) | `fabric init` and `preflight-prod`: queue against free disk |
| 6. Read a run back | [read a run](../reference/manual-setup/production-setup.md#6-read-a-run) | `fabric verify --kubernetes` | the reader's verdict |
| 7. Upgrade | [upgrade](upgrade.md) | [upgrade](upgrade.md) | |

On Kubernetes the whole path is checked today:
[Get started with Kubernetes](../get-started/kubernetes.md) installs the
production profile with the host sensor and verifies a run.
